---
title: "Describe a company as code"
type: claim
by: "Andy Smith"
status: "tentative"
---

Reflection.dev's central thesis: an entire company — its processes, shared context, roles, and agent roster — can be described as code and executed, with humans setting the rules of how it evolves. An organization becomes a single executable system rather than a set of people each doing ad hoc parts of the work ([[An organization is one assembly line, not many craftsmen]]).

This extends [[Infrastructure as code (en.wikipedia.org)|Infrastructure as Code]] from machines to the whole organization: the same promises — versioned, reviewable, reproducible, auditable — and the same risks, since executable organization definitions can drift from reality and carry misconfiguration-as-vulnerability. The standing challenge is whether it captures what [[Business process management (en.wikipedia.org)|business process management]] could not ([[Does company as code repeat the failures of business process management?]]).
