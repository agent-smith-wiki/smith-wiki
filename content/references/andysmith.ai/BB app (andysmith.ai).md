## Summary
A short link-note pointing at [getbb.app](https://getbb.app/), described as "a harness that supposedly can modify itself." Andy reads it as essentially the same thing he is building in [[Zeno]] — but implemented in NodeJS instead of Lisp — and states his habit of watching what use cases such projects attract so he can cover the same ones in Zeno, more elegantly.

## Key ideas
- The BB project is a [[self-modifying code|self-modifying]] [[agent harness]] — the scare-quote "supposedly" signals healthy skepticism that such a harness actually can rewrite itself in practice.
- For Andy the differentiator is not the concept but the stack: BB is what Zeno is, in NodeJS rather than Lisp.
- His explicit working practice: monitor other agent-harness projects for the [[AI agents|use cases they surface]], then implement those same use cases in Zeno "more elegantly."
- The post implies Zeno's competitive edge will be elegance (a Lisp-based design), not feature novelty.

## Conclusions
This is a one-paragraph comparative/competitive note, not an argument. The underlying claim is that self-modifying agent harnesses are becoming a recognizable category being built independently in multiple languages, and that Zeno should stay ahead by covering whatever use cases those projects discover — implemented more elegantly in Lisp.
